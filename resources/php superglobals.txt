# Superglobals

Superglobals — Built-in variables that are always available in all scopes

### Description [¶](https://www.google.com/url?sa=E&amp;q=https%3A%2F%2Fwww.php.net%2Fmanual%2Fen%2Flanguage.variables.superglobals.php%23refsect1-language.variables.superglobals-description)

Several predefined variables in PHP are "superglobals", which means they are available in all scopes throughout a script. There is no need to do **global $variable;** to access them within functions or methods.

These superglobal variables are:

* `[$GLOBALS](https://www.php.net/manual/en/reserved.variables.globals.php)`
* `[$_SERVER](https://www.php.net/manual/en/reserved.variables.server.php)`
* `[$_GET](https://www.php.net/manual/en/reserved.variables.get.php)`
* `[$_POST](https://www.php.net/manual/en/reserved.variables.post.php)`
* `[$_FILES](https://www.php.net/manual/en/reserved.variables.files.php)`
* `[$_COOKIE](https://www.php.net/manual/en/reserved.variables.cookies.php)`
* `[$_SESSION](https://www.php.net/manual/en/reserved.variables.session.php)`
* `[$_REQUEST](https://www.php.net/manual/en/reserved.variables.request.php)`
* `[$_ENV](https://www.php.net/manual/en/reserved.variables.environment.php)`

### Notes [¶](https://www.google.com/url?sa=E&amp;q=https%3A%2F%2Fwww.php.net%2Fmanual%2Fen%2Flanguage.variables.superglobals.php%23refsect1-language.variables.superglobals-notes)

**Note**: **Variable availability**

By default, all of the superglobals are available but there are directives that affect this availability. For further information, refer to the documentation for [variables\_order](https://www.google.com/url?sa=E&amp;q=https%3A%2F%2Fwww.php.net%2Fmanual%2Fen%2Fini.core.php%23ini.variables-order).

**Note**: **Variable variables**

Superglobals cannot be used as [variable variables](https://www.google.com/url?sa=E&amp;q=https%3A%2F%2Fwww.php.net%2Fmanual%2Fen%2Flanguage.variables.variable.php) inside functions or class methods.

```
Since PHP 5.4, you cannot use a superglobal as the parameter to a function. This causes a fatal error:

function foo($_GET) {
  // whatever
}

It's called "shadowing" a superglobal, and I don't know why people ever did it, but I've seen it out there. The easy fix is just to rename the variable $get in the function, assuming that name is unique. 

There was no deprecation warning issued in previous versions of PHP, according to my testing, neither in 5.3 nor 5.2. The error messages in 5.4 are:
Fatal error: Cannot re-assign auto-global variable _GET in...
Fatal error: Cannot re-assign auto-global variable _COOKIE in...
etc.
```
