CSRF Token in PHP: A Complete and Secure Guide
Modern web applications must protect the actions of authenticated users. One of the most common vulnerabilities is Cross-Site Request Forgery (CSRF): an attack in which a malicious website tricks an authenticated user's browser into sending unintended requests to a legitimate application.

The CSRF token is one of the strongest and most universally accepted defenses against this type of attack, especially when handling operations that modify the system state.

What is a CSRF Token?
A CSRF token is a cryptographically secure string generated by the server and associated with the user's session. The token is sent with every sensitive request and verified by the server before accepting the transaction.

Why CSRF is dangerous
Leverage existing user authentication
Does not require credential theft
Can modify data, settings or perform critical actions
Correct operating model
Server-side token generation
Inserting the token into the request
Server-side verification with secure comparison
Token expiration and rotation
Implementation in PHP
Secure session management
<?php
session_start();
ini_set('session.cookie_httponly', '1');
ini_set('session.use_strict_mode', '1');
?>
Token generation and verification
<?php
function csrf_generate(): string {
    $token = bin2hex(random_bytes(32));
    $_SESSION['csrf_token'] = $token;
    $_SESSION['csrf_time'] = time();
    return $token;
}

function csrf_verify(string $token, int $ttl = 900): bool {
    if (!isset($_SESSION['csrf_token'], $_SESSION['csrf_time'])) {
        return false;
    }
    if ((time() - $_SESSION['csrf_time']) > $ttl) {
        return false;
    }
    return hash_equals($_SESSION['csrf_token'], $token);
}
?>
Inserting into the HTML form
<input type="hidden" name="csrf_token"
value="<?= htmlspecialchars(csrf_generate(), ENT_QUOTES) ?>">
Server-side verification
<?php
if (!csrf_verify($_POST['csrf_token'] ?? '')) {
    http_response_code(400);
    exit('Richiesta non valida');
}
?>
Fundamental best practices
Always use HTTPS
Token with time expiration
Comparison with hash_equals()
Regenerate the token after critical operations
Don't rely solely on SameSite cookies
CSRF and XSS
The CSRF token does not protect against XSS vulnerabilities. If a malicious script can be executed in the user's browser, the token can be read and reused. CSRF protection must always be accompanied by proper output sanitization and CSP policies.

Conclusion
Proper use of CSRF tokens is a minimum security standard for any modern PHP application. It's a simple, effective defense with minimal implementation cost compared to the potential damage it prevents.

Complete example: form + CSRF verification
Below is a minimal but complete example that shows the entire CSRF protection flow in PHP: token generation, form submission, and server-side verification.

index.php – Form Page
<?php
session_start();
ini_set('session.cookie_httponly', '1');
ini_set('session.use_strict_mode', '1');

function csrf_generate(): string {
    if (empty($_SESSION['csrf_token'])) {
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
        $_SESSION['csrf_time'] = time();
    }
    return $_SESSION['csrf_token'];
}
?>

<!DOCTYPE html>
<html lang="it">
<head>
    <meta charset="UTF-8">
    <title>Form protetto da CSRF</title>
</head>
<body>

<form method="post" action="process.php">
    <input type="hidden" name="csrf_token"
           value="<?= htmlspecialchars(csrf_generate(), ENT_QUOTES, 'UTF-8') ?>">

    <label>Nome</label>
    <input type="text" name="name" required>

    <button type="submit">Invia</button>
</form>

</body>
</html>
process.php – Token Verification
<?php
session_start();
ini_set('session.cookie_httponly', '1');
ini_set('session.use_strict_mode', '1');

function csrf_verify(string $token, int $ttl = 900): bool {
    if (!isset($_SESSION['csrf_token'], $_SESSION['csrf_time'])) {
        return false;
    }
    if ((time() - $_SESSION['csrf_time']) > $ttl) {
        return false;
    }
    return hash_equals($_SESSION['csrf_token'], $token);
}

if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    http_response_code(405);
    exit('Metodo non consentito');
}

if (!csrf_verify($_POST['csrf_token'] ?? '')) {
    http_response_code(400);
    exit('Richiesta non valida');
}

// Token valido: qui puoi processare i dati
echo 'Form inviato correttamente';

// Rotazione del token dopo l’uso
unset($_SESSION['csrf_token'], $_SESSION['csrf_time']);
 


This pattern is sufficient for most classic PHP applications and represents a solid foundation to extend for more complex cases (AJAX, multiple forms, tokens per action).
